	- Learning to Learn
		- Front-Load Your Learning
			- Spend first few months on the job learning how everything works (i need to go back and do this)
			- Start with your domain - then look to the upstream and downstream
			- Even when you want to get your hands dirty - this is an investment that is worthwhile
		- Learn by Doing
			- Even while reading docs, make sure to do SOMETHING! Know the impact of your work
			- ex. write a unit test instead of updating an index on a high traffic database
		- Experiment with Code
			- Run experiments to see how code works or fails
		- Read
			- Don't try to read everything at once, start with team docs and design documents.
				- pay attention to discussions on trade-offs
			- read YOUR codebase as well as high quality open source code
			- Read through pending tickets and issues to see what everyone is working on and what is coming up
				- backlog is good source for newbie projects too
				- Join a reading group!
