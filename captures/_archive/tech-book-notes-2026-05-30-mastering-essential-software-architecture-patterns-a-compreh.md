## Summary
This guide clarifies the distinction between software architecture (high-level system structure and non-functional requirements) and software design (detailed component implementation), emphasizing the C4 model for visualizing architecture across four abstraction levels. It advocates for pattern selection based on project needs to ensure scalability, maintainability, and adaptability.

## Key Points
- Architecture defines system structure, components, and NFRs (scalability, security), while design focuses on implementation details of components.
- The C4 model uses Context, Container, Component, and Code diagrams to simplify architecture communication and collaboration.
- Pattern selection (e.g., monolithic, microservices, event-driven) must align with project goals to balance complexity and future-proofing.
- Architecture and design work interdependently: architecture sets constraints, design executes within them.
